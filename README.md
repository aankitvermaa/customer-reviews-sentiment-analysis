# Amazon Review Sentiment Analysis

A full ML pipeline that classifies Amazon product reviews as **Positive** or **Negative**. Built with TF-IDF features, classical linear classifiers (NB, LogReg, SVM), and a Streamlit frontend for trying it out.

I built this to practice the complete ML workflow — from raw data to a deployed app, with proper experimentation and evaluation along the way.

## Dataset

Amazon customer reviews, binary polarity. Supported layouts (auto-detected by `src/data_loader.py`):

| Dataset | File | Labels |
|---|---|---|
| Amazon Reviews for Sentiment Analysis (Kaggle, `bittlingmayer/amazonreviews`) | `train.ft.txt.bz2` | `__label__1` = negative, `__label__2` = positive |
| Amazon Reviews Polarity (CSV) | `train.csv` (headerless: polarity, title, text) | 1 = negative, 2 = positive |
| Amazon Fine Food Reviews (Kaggle) | `Reviews.csv` | Score 4-5 positive, 1-2 negative, 3 dropped |

Place the file in `data/raw/`. It is excluded from Git. Check the dataset's licence/terms on its source page before redistributing anything.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python -m src.eda   --data data/raw/train.ft.txt.bz2 --sample-size 100000
python -m src.train --data data/raw/train.ft.txt.bz2 --sample-size 100000 --cv 5 --n-jobs 2
streamlit run app/app.py
pytest
```

`--sample-size` bounds the number of reviews used (default 100,000) so the full experiment grid runs on a laptop. Raise it for a larger run.

## Methodology

- **Split:** stratified 80/20, seed 42. Test set only used once at the end.
- **Preprocessing:** I tried 3 modes — minimal (just cleaning), stopwords (keeping negations), and stemming. Minimal worked best.
- **Features:** TF-IDF with unigram+bigram, 50k vocab, sublinear TF.
- **Models:** Compared Naive Bayes, Logistic Regression, and Linear SVM. SVM won.
- **Selection:** 5-fold stratified CV on training data, optimizing F1. Ran experiments in stages (model → n-grams → vocab → preprocessing → tuning).
- **Final artifact:** `models/sentiment_pipeline.pkl` — cleaner + TF-IDF + classifier in one sklearn Pipeline.
- **Error analysis:** looked at misclassified reviews and tagged them by likely cause (negation, mixed sentiment, short review, etc.).

## Results

All numbers are generated by `src.train` and written to `reports/`:

- `reports/RESULTS.md` - selected configuration, CV score, test metrics, all experiments
- `reports/experiments.csv`, `reports/metrics.json`
- `reports/figures/` - EDA plots and confusion matrix
- `reports/top_features.csv` - strongest positive/negative n-grams
- `reports/error_analysis.csv` - sampled misclassifications

## Known limitations

- Binary only — no neutral class.
- Bag-of-words can't handle sarcasm or long-range context.
- Trained on English Amazon reviews, probably won't generalize well to other domains.
- Uses a subsample by default (100k reviews) — increase `--sample-size` for better results.
